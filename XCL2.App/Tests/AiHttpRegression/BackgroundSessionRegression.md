# 后台会话保护回归

`BackgroundSessionCases.RunAsync()` 由 HTTP 回归主程序调用，使用真实 `AiAssistantService`、任务存储和工作模式策略；HTTP 响应及 Windows 文件执行器由测试替身提供。

自动覆盖：

- 旧 Build 会话等待响应时，新会话切到 Chat 或 Plan 并完成，旧会话仍按自身模式继续工具链并独立保存结果。
- 显式把运行中的原会话切到 Plan 或 Chat，下一次工具请求仍被拒绝；只读崩溃分析边界不能被会话回调提升。
- 请求模式跨 await 继承，子任务的嵌套模式不污染父任务，释放作用域后恢复周围模式，收紧后不能重新提升当前轮权限。
- 停止新前台会话不会取消旧后台请求。

运行：

```powershell
dotnet run --project Tests/AiHttpRegression/AiHttpRegression.csproj
```

Windows 手动验证（真实 WPF / Shell 进程）：

1. 在 Build 会话批准一个耗时约 45 秒、超时设为 90 秒的测试命令，记下执行卡片中的进程 PID。
2. 点“新建会话”，选择“保留后台并新建”；确认默认按钮也是该选项。将新会话切到 Chat，发送普通问题并停止这条新请求，旧 PID 应继续运行到正常结束。
3. 返回旧会话，应保留执行卡片、输出及原来的工作模式。只点该会话的“停止”时才取消它自身的请求和命令进程树。
4. 在原会话等待模型响应时切为 Plan/Chat，后续执行请求应被拒绝；立刻切回 Build 也不会提升仍在运行的这一轮。需要执行时发送下一条消息。
5. 旧会话停留在提问卡片时保留后台，新会话再触发另一个问题；切回时各自的问题和回答应保持独立。

命令自身设定的超时、用户显式停止及启动器退出仍可结束命令；后台保护不会取消这些限制。
