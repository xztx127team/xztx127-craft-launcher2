# AI 多接口与退出保存

## 使用方式

1. 在 AI 助手设置中选择命名接口，填写该接口的地址与密钥，再拉取该接口的模型。模型列表保留接口身份，不同接口的同名模型可以并存。
2. 模型拉取和聊天请求共用地址解析，支持 Base URL、完整 `/chat/completions` 或 `/models` 地址，以及地址中的查询参数。
3. 密钥属于各自接口；同接口备用密钥按设置轮换，跨接口切换仍由独立开关控制。免密接口可以不填写密钥。
4. 修改设置后按 Esc，会提示保存、放弃修改或继续编辑。保存校验失败时继续停留在设置中；未修改时直接退出。

## 本轮修复

- 修正完整聊天地址被重复追加请求路径、查询参数拼接位置错误的问题。
- 修正残留的独立供应商字段覆盖当前选择的模型拉取接口的问题。
- 修正切换命名接口时未添加的密钥丢失问题，避免将密钥错配到其他接口。
- 将未保存提示接入实际的 Overlay 退出路径，避免主窗口提前处理 Esc 直接关闭设置。

## Windows 验收

- 配置两个接口及不同密钥，分别选择并拉取模型，确认请求地址和模型归属正确。
- 在第一个接口输入密钥后直接切换到第二个接口，返回检查密钥仍属于第一个接口。
- 分别使用 Base URL、完整聊天地址和完整模型列表地址，验证拉取与模型测试。
- 对失效密钥、接口权限不足、普通参数错误及临时服务器错误，确认按各自错误类别处理，且不混用其他接口密钥。
- 修改地址、密钥、模型列表或其他选项后按 Esc，分别验证保存、放弃修改、继续编辑；无修改时不提示。
- 保存内容无效时选择保存，确认设置窗口保持打开，修正后可再次保存。
- 验证未保存提示不会改变其他弹窗的 Esc 行为；保留本包中此前的编译和彩蛋修复。

当前环境没有 .NET SDK，附带的 C# 回归需要在具备 SDK 的环境执行。静态检查不能替代 Windows 编译、界面操作及供应商接口实测。
