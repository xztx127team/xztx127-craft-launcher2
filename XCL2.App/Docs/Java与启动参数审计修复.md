# Java 与启动参数审计修复

本次修正实际调用链，未将源码静态检查写成 Windows 运行验收。

| 问题 | 实际接入的修复 | 验证边界 |
|---|---|---|
| Java 探测的 5 秒超时位于阻塞读取之后 | 同步匹配与异步扫描共用 `JavaProcessProbe`；stdout/stderr 并发排空，等待截止包含管道读取；超时或取消结束探测进程树；保留输出最多各 65,536 个字符 | 增加真实子进程 fixture 回归，当前环境没有 .NET SDK，未运行 |
| 自动 Java 搜索堵塞主窗口 | 主窗口先抓取 Java 路径快照，实际查找在后台执行，并传递启动取消令牌 | 需要 Windows 实测取消、异常 Java/shim、杀毒软件环境 |
| Java 在原路径升级后，登记版本缓存失真 | 自动匹配实际探测当前文件；不使用登记的主版本号决定可用性；显式切换匹配版本也重新探测 | 未在多 Java 真实安装环境运行 |
| 多层继承漏掉祖父参数、库、客户端 | 完整解析最多 64 层，检测循环、缺失父版本、无效目录名；真实启动和缺库检查共同使用；参数根到子合并，子库覆盖父库，客户端跟随真实所有者或显式 jar 引用 | 新回归直接链接完整 `LauncherService.cs` 并调用真实参数预览；未运行真实游戏/模组加载器 |
| 普通模式仍应用实例历史 JVM 参数 | 普通模式同时排除实例和全局保存的自定义 JVM 参数；明确命令行请求仍作为本次会话意图生效 | 纯策略回归已加入，未执行 C# |
| JVM 条件参数只识别 Windows 名称 | arch 按所选 Java PE 架构判定，version 用 Windows 版本正则匹配；保留最后匹配规则优先；无效/超时正则不匹配 | 策略与真实构建回归包含 x86/amd64 和不同 Windows 版本用例；未执行 C# |
| 三层实例检查和修复路径不同、改名后 client 写错目录 | 版本列表、完整性检查、真实启动与修复共用继承解析结果；库按合并结果补全，资源用继承后的索引；client 下载显式区分文件夹名与原 JSON ID；缺父元数据按官方清单逐层恢复，不可恢复的自定义描述明确报错 | 生产修复计划 fixture 覆盖原 metadata ID 不被修改、实际目录/JAR 名以及显式 jar 重定向；未执行 C# 或真实网络修复 |
| x64 Windows 与 x86 Java 的库/本机 DLL 口径不同 | 实际启动把 Java PE 架构传到库合并、检查、补库和重试；非系统默认架构的旧 classifier DLL 使用独立 `natives/java-x86` 等目录，避免覆盖默认架构 DLL；缺少匹配架构 DLL 进入现有补库流程 | 目录检查只确认至少一个同架构 DLL，不代替逐 DLL 功能验收；手动补全优先已明确选择的 Java，未明确时用系统架构。未实测 Windows 原生库加载 |
| 命令行成功解析却没有效果 | 下表中的选项有真实消费者；其余 19 个旧选项明确报错并停止动作，帮助不再承诺兼容空操作 | 解析回归已更新，未执行 C#；不宣称实现全部旧选项 |

本次会话支持的补充选项：

| 选项 | 行为 |
|---|---|
| `--skip-update-check` | 跳过本次启动器自动更新检查 |
| `--java <路径>` | 真实游戏启动使用该文件；不存在时明确错误 |
| `--jvm-args=<参数>` | 本次 JVM 参数追加在允许使用的保存参数之后；不修改设置 |
| `--game-args=<参数>` | 向真实游戏参数追加内容；引号不闭合时在启动前拒绝 |
| `--server <地址>` | 仅在客户端清单声明 Quick Play 服务器参数时启用；不支持时明确说明 |
| `--fullscreen` | 向支持现代参数布局的客户端传入全屏；远古位置身份参数客户端明确说明暂不支持 |

手动平台验收仍需检查：Java 8 启动远古版本、Java 17/21/25 对应客户端、x86 Java 在 x64 Windows 上的条件参数、三层加载器实例、改名版本目录、Quick Play 服务器启动、暂停/取消 Java 探测。这里未证明所有第三方加载器或将来的清单格式兼容。
