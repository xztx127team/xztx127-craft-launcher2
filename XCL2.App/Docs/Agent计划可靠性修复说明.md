# Agent 计划可靠性修复

截图中的失败发生在计划尚未保存时：模型把 HTML 内容放入工具 JSON，转义出错；之后反复说“先建立计划”，却没有发出可保存的协议。原流程把这种正文当成最终回答，用户只能不断发送“继续”。

本次修复把这类错误恢复到独立的计划阶段。同一轮内要求模型提交完整文本 Plan，收到保存成功的反馈后再请求具体工具。没有把普通正文转换成计划，也没有自动修补可执行 JSON。连续三次无效回复会停止自动修正，明确说明 Plan 未保存、被拦截的工具未执行。普通回答、必要提问和拒绝说明仍能直接结束回复。

## 兼容格式

保留原来的 `update_task` JSON；推荐独立文本协议：

```text
<<XCL2_PLAN>>
○ [inspect] 读取项目并核对现状
- [change] 修改文件
- [verify] 验证结果
<</XCL2_PLAN>>
```

支持完整末尾代码围栏、ASCII 短横线和 Markdown 复选框：`- [~]` 正在进行、`- [x]` 已完成、`- [ ]` 未开始。明确状态的编号步骤也可使用。仍拒绝未闭合、混合工具请求、尾随正文、多个正在进行步骤及超长数据；不从更大的源码片段中抽取控制标记。

## 保存与执行

- 每轮 Agent 首次保存必须显式提交完整非空步骤列表，继续任务也适用；只更新备注不能绕过计划要求。
- 初次提交全为 pending 时，只把第一项设为正在进行。后续更新、Plan/Build 模式及包含已完成或受阻步骤的计划不自动开始步骤。
- 步骤 ID 优先使用明确值。省略时，只匹配新旧列表中均唯一的同名步骤；其余生成不冲突的 ID。调整顺序不会把其他步骤的证据移过来。遗漏状态或证据保留旧值，显式空证据则清空。
- 参数错误在实际保存前检查，Agent 的继承状态冲突不会消耗有限工具预算。只有保存成功才设置本轮计划就绪并刷新右侧 Plan。
- 任务读写失败停止执行；即使任务状态无法保存，也尽量保留会话中的失败说明。不可读任务不会被提示为已保存，不恢复已删除任务。
- 计划格式和恢复机制不授予文件、Shell、鼠标键盘权限，不切换用户选择的工作模式，不重放被拦截或已完成的操作。

## 回归与验证

`Tests/AiPlanRegression` 检查协议围栏、状态写法、边界和旧步骤身份/证据保留。`Tests/AiHttpRegression` 使用模拟 HTTP 服务检查生产发送流程，包括截图中的错误 JSON、纯正文计划承诺、有限重试、取消、模式边界和持久化。

有 .NET 8 的环境可执行：

```sh
dotnet run --project Tests/AiPlanRegression/AiPlanRegression.csproj
dotnet run --project Tests/AiHttpRegression/AiHttpRegression.csproj
```

当前环境未安装 .NET SDK，未编译或执行上述 C# 回归，也未进行 Windows 界面验证。已执行随源码附带的静态检查，检查项目依赖、XML/XAML 与事件引用等结构；静态检查不能代替编译和运行验证。
