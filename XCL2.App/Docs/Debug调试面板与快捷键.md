# Debug 调试面板

使用 `XCL2.exe --debug` 启动本次会话后，在启动器主窗口按 F3 查看类似 Minecraft F3 的文字调试面板。使用 `XCL2.exe --debug --help` 查看命令行中的同一份快捷键说明。旧 `--debug-console` 尚未支持，传入会明确报错；请使用 `--debug`。

| 按键 | 操作 |
| --- | --- |
| F3 | 松开时显示 / 隐藏面板 |
| F3 + H | 显示快捷键帮助 |
| F3 + O | 运行总览：窗口、DPI、CPU、内存、下载和进程数 |
| F3 + S | 系统视图：CPU、总/已用/可用内存、托管堆、GC 次数、线程数、WPF 渲染级别 |
| F3 + G | 游戏视图：各游戏进程 PID、CPU、物理内存 |
| F3 + R | 暂停 / 继续采样，暂停时冻结当前读数 |
| F3 + M | 打开性能悬浮窗详细设置 |
| F3 + L | 打开原有日志页 |
| F3 + D | 打开 / 收起右上角统一下载管理 |
| F3 + P | 打开原有设置页 |
| F3 + C | 复制运行概况 |
| F3 + Esc | 关闭面板 |

组合键需要先按住 F3，再按对应按键。长按与键盘重复消息不会重复触发；组合键执行后，松开 F3 不会再误切换面板。未定义的 F3 组合会被消费，防止误触当前按钮或删除操作。输入框、密码框、原生嵌入窗口、模态弹窗以及不活动的窗口保留原有键盘操作；没有系统级键盘钩子，不拦截游戏或其他程序。

`--debug-panel` 或 `--调试面板` 同时开启调试模式并在首帧后显示面板。面板内的总览、系统、游戏和暂停按钮也可直接点击。未完成首次协议与引导时不自动执行页面跳转等启动动作。WPF 渲染级别不是 Minecraft FPS。

面板显示实际的启动器版本、.NET 版本、进程位数、当前页面种类、窗口尺寸/状态/缩放、实际预览和置顶状态、基本模式、运行时长、逻辑处理器数量、系统与启动器 CPU、系统总/可用内存、启动器工作集和托管堆，以及游戏进程和下载数量。CPU 按整机总算力计算，首轮需要建立基线；缺失数据明确显示暂无数据。

面板只在显示且主窗口活动时每秒采样，隐藏或失活后停止。正常采样时清空旧缓存，重新打开先建立基线；手动暂停时保留冻结读数并明确标记，切换视图、隐藏后再打开仍保持冻结，继续时重新建立 CPU 基线。暂停不影响独立性能悬浮窗。独立性能窗口已有新鲜样本时会复用；失败不把旧读数伪装成实时数据。

复制的摘要仅从数值、版本号和固定枚举生成，不包含账户、实例名称、文件路径、原始命令行、凭据或日志正文。日志与设置入口仍使用原有页面处理器及基本模式限制，离开未保存的设置页仍会询问。

实现：`Views/MainWindow.Debug.cs`，纯按键状态与共享帮助在 `Services/LauncherDebugShortcuts.cs`，摘要模型在 `Services/LauncherDebugSnapshot.cs`。回归位于 `Tests/DebugShortcutsRegression`。当前环境执行了静态结构检查；没有可用 .NET SDK 和 Windows 桌面，未在此编译或进行实际键盘/窗口验证。
