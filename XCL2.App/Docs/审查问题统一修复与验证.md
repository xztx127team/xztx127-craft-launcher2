## 需要知道的行为边界

- 配置多开时，两个进程改同一个标量或同一个数组会提示冲突并保留磁盘内容。请重新打开产生冲突的启动器后再修改；这里没有猜测用户希望覆盖哪一份。其他进程的设置不会即时刷新到当前已打开界面。
- 删除会话遇到不可读的其他历史记录时，可能暂时保留附件缓存；这比删除仍被引用的文件更稳妥。
- 纯聊天默认窗口上限为 80 条消息、约 24k Token、8 张图和 20 MiB 图片，并按已配置的模型窗口收紧。当前单条输入过大时明确提示，不静默截断用户输入。
- 下载的跨进程空锁文件会保留在目标目录；它们不是续传数据。不能在某个下载结束后直接删锁文件，否则另一个等待中的进程可能绕过持有者。
- 自动更新依赖发布附件提供有效大小和 SHA256；旧发布若没有这些元数据，会拒绝自动应用并说明手动更新入口。重启后的 5 秒存活探测不代表完整健康检查。若关闭时无法写入授权文件，旧 EXE 保留，用户需要重新打开；回滚失败会在日志中保留备份位置供恢复。
- CurseForge 清单本身不能标明每个模组适用于客户端还是服务端。服务端导入会说明限制，不会静默更换服务器核心；缺少官方授权 URL、大小或哈希时拒绝自动下载，不猜测 CDN 地址。
- 有界实时日志视图与基于该视图取得的摘要不会包含全部较早内容；正常关闭时的会话文件由暂存前缀与当前尾部构成。磁盘写入失败会明确标注可能缺失，不能保证故障或进程被强制结束时得到完整会话文件。
- `--java`、`--jvm-args`、`--game-args`、`--server`、`--fullscreen`、`--skip-update-check` 是本次接入的补充参数。其余此前无效果的选项目前会明确报告“尚未支持”，并停止该次请求；完整列表见 `--help`。
- 愚人节的 7 段阅读确认、8 个小游戏和本地人机步骤继续保留，卡住 2 次或 20 秒的配置关闭提示也保留；此修复没有移除恢复入口。真实交互和鼠标轨迹仍需 Windows 验收。

## 验证结果如何阅读

本次实际执行结果放在 `Tests/AuditFixValidation/verification-status.json`。源码静态检查的资源键去重、XAML 事件名称、项目依赖等分项统计保存在同目录。资源键去重的数量不能当作功能测试数量。静态报告的空 warnings 数组不代表 C# 编译零警告。

旧的 `Ux30Validation`、`Ux50Validation` 和其他历史 JSON 报告对应之前的交付，保留作历史记录；本次状态以 `AuditFixValidation` 为准。

在 Windows 安装 .NET 8 SDK 后，从源码目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Tests\Test-Ux30.ps1
```

脚本构建主程序，再逐个执行回归项目；默认构建截止 300 秒、每个项目 180 秒，可用 `-BuildTimeoutSeconds`、`-TestTimeoutSeconds` 调整。每个项目保留输出日志，并持续更新 `Tests/ux30-windows-results.json`。卡住的项目会记录为 `timed_out`，不会算通过。`-SkipRegression` 会明确记为跳过。

即使该脚本通过，仍需手动检查高 DPI/窄窗口布局、动画首帧、连续开关弹窗、切换日志、触屏、旧版 Minecraft 与第三方加载器、真实微软登录、更新替换/回滚，以及游戏运行期间的性能悬浮窗。这些项目无法在当前环境完成。
