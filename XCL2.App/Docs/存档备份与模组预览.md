# 存档备份与模组预览

这组入口只出现在对应页面：存档页面的“备份 / 恢复副本”、实例菜单的“存档备份”、模组管理页面的“兼容性预览”。导入导出整合包及前置修复收在模组页面的“更多”菜单，更新详情默认折叠，不增加主窗口常驻按钮。

## 存档备份

- 手动备份立即可用。自动备份默认关闭，由用户按存档开启，并设置间隔（1–720 小时）、位置、保留数量（1–100）。
- 不替代已有的整个实例备份或启动/退出备份；新功能仅打包该世界目录。
- 默认位置为启动器数据目录下 `save_backups`。改变位置不移动或删除旧备份；手动备份不会被自动保留规则删除。
- 只允许本地已配置游戏目录中的存档参加自动计划；手动打开的其他存档仍可手动备份。
- 仅在启动器运行时按 15 分钟检查间隔执行，启用后首次检查约 2 分钟；没有已启用计划时不创建定时器。
- 备份之前读取游戏进程列表；同目录的游戏或无法确定目录的外部游戏仍在运行时跳过自动备份，手动操作会提示先退出游戏。同时在整个复制期间持有 session.lock 的排他共享/字节锁，避免游戏或服务器在检查后打开该存档；锁标记不打入备份。文件长度或修改时间发生变化、增删文件时，放弃这份未完成备份。
- 新备份记录文件数量、原始大小、创建时间及 ZIP 的 SHA-256。备份取消或失败会清理本次临时文件。
- 恢复先展示时间、大小和目标目录。恢复始终创建原存档旁的新副本，已有目录一律拒绝，不提供覆盖原存档的快捷选项。
- 恢复前校验 ZIP 哈希、所有条目路径/重复文件、文件数量与未压缩大小，检查目标磁盘空间；完整解压到临时目录后才改名成为可见副本。
- 拒绝链接/重解析目录、压缩包链接、目录穿越、Windows 设备名等；备份/恢复保护上限为 10 万文件、100 GB、128 层目录。每个存档、每个备份位置最多 10,000 份记录，达到上限时提示整理或更换位置，不会静默截断列表。超过保护上限时说明原因，不改原存档。
- 取消按钮在工作期间请求取消，结束后可关闭。长时间的复制和哈希均在后台完成，并检查取消信号。

## 模组兼容性预览

- 用户点击后才读取本地 JAR；不联网、不安装、不启用、不删除文件。
- 对 Fabric / Quilt 及 Forge / NeoForge 常见元数据读取加载器、依赖 ID 与版本要求。会读取第一层内嵌 Fabric 模组，避免把常见 API 子模块当作缺少。
- 已禁用文件不参加已安装依赖判断。缺失依赖、明显的加载器不匹配和可识别的 Minecraft 数字范围不匹配以建议列出。
- 这不是完整的加载器解析器：复杂范围、依赖版本匹配、深层内嵌模组、服务端/客户端环境和运行期冲突仍需加载器验证。未识别的文件和范围明确标注，不显示“完全兼容”。旧 mods.toml 可能被早期 NeoForge 使用：明确的 forge/neoforge 必需依赖用于区分；只有旧描述且未声明时提示“加载器需要核对”，不断言二者通用。
- “联网检查设置”只控制此页面手动点击检查更新的入口；默认允许，用户可关闭。关闭后点击更新会说明在哪里开启；已有模组自动更新提醒偏好不被覆盖。

## 更新前查看说明

- 在选择更新的清单中，版本变化始终可见；适配游戏/加载器、依赖声明、更新说明放在每项的折叠区域。
- 这些内容来自本次检查更新已经收到的 Modrinth 响应，不增加逐项说明的后台请求；原始更新说明按纯文本显示，不执行 HTML 或脚本。
- 模组选择/更新仍由用户确认，依赖不会自动安装。既有更新前文件快照、下载哈希校验与回滚保护保持不变。
- 元数据字段依照 Modrinth 官方 List project's versions API：<https://docs.modrinth.com/api/operations/getprojectversions/>。

## 验证边界

`Tests/UxBackupsModsRegression` 链接实际生产服务，覆盖副本恢复保留后续进度、校验失败不写入、恶意路径、自动备份保留不删手动备份、取消清理以及本地模组判定。没有 .NET SDK 的环境只能检查源码、XML和接线，不能宣称这些 C# 测试已运行。

Windows 验收还需检查：开启/关闭自动计划的定时器生命周期、进程发现与退出竞态、磁盘空间错误、取消大存档、长名字/缩放/窄窗口下的折叠区和操作按钮，以及已有实例备份行为不受影响。
