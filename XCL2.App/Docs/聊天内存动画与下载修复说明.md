# 纯聊天、内存、旧版启动与动画/下载修复

## 纯聊天模式

在 AI 助手和 AI 设置的模式选择中新增「纯聊天模式」，旧枚举值保持不变。使用独立聊天提示词，不注入工作目录、权限清单、文件/命令协议、旧任务断点或旧执行摘要。实际工具分发也限制该模式，不能靠回复中的控制标记执行命令、操作电脑、保存任务或申请目录。

只有本轮明确要求读取日志、日志分析开关已开启且用户确认时，才允许读取本次启动器日志。普通日志知识问答或否定读取要求不会启用日志工具。聊天模式不修改为其他模式保存的权限设置。图片可继续用于聊天，压缩包及其临时目录不带入聊天上下文。

## JVM 内存

在设置中的「JVM 内存分配」打开动态分配，可选：

| 模式 | 默认最小堆 | 默认最大堆 | 计算方式 |
| --- | --- | --- | --- |
| 动态范围 | 500MB | 8192MB | 最大值同时参考总物理内存的 70% |
| 总内存百分比 | 总量的 5% | 总量的 70% | 始终以总物理内存为基数 |

阈值可以修改，也可填写固定 MB 值。极小内存机器按物理上限收敛，固定值被收敛时会说明本次实际值。内存显示可选择总量或剩余量，显示选择不改变百分比的计算基数。

实际启动和启动脚本导出使用同一计算入口。启用动态分配后，每次启动都重新采样；「启动器打开时」只额外预览，不把计算结果写回手动设置。旧配置的手动模式保留；实例手动值优先，实例明确启用动态模式时按动态策略计算。自动生成的堆大小适配检测到的 32 位 Java；手动或明确固定值保留，由 JVM 检查给出过大堆提示。

## 旧版 Minecraft

修复 1.0 等旧版本的位置参数与现代通用参数混用，补齐玩家名、会话和游戏目录变量；根据旧资源索引准备对应资源目录。Java 选择优先使用版本元数据及继承链；缺少声明时按真实版本号回退，修正重命名目录和旧版 Java 匹配问题。详见同目录的《旧版Minecraft启动参数修复说明》。

## 动画与下载

弹窗及窗口恢复现在真正创建缩放动画。弹窗布局与首帧完成后再启动过渡；合成通知超时但布局有效时继续播放。关闭、覆盖、禁用动画等路径正确收尾，过期回调不会重新激活旧弹窗。初始开窗先显示可见起点，布局后播放动画，并延后插件界面初始化；动画被窗口状态变化打断时仍有独立初始化兜底。

Java 下载、DirectX、基岩版 VC++/UWP 补全和启动皮肤补丁进入右上角统一下载管理。已在下载流水线中的运行库补全复用当前条目。下载阶段可以取消，系统安装器启动后等待真实退出，避免误报完成或过早删除安装包。失败或取消的前置任务不会在后台重试后继续旧的游戏启动。当前项目没有 JetBrains 安装流程。

## 验证范围

新增内存分配、旧版启动兼容的独立回归项目；扩展 AI HTTP/权限、下载队列和 WPF 弹窗回归。静态检查涵盖项目依赖、XML/XAML、事件绑定与相关源码契约。当前环境没有 .NET SDK，未编译或执行 C# 回归，也未进行 Windows 游戏启动、安装器或界面实测。

可在配置了 .NET 8 的环境执行便携回归：

```sh
dotnet run --project Tests/MemoryAllocationRegression/MemoryAllocationRegression.csproj
dotnet run --project Tests/LegacyLaunchRegression/LegacyLaunchRegression.csproj
dotnet run --project Tests/AiHttpRegression/AiHttpRegression.csproj
dotnet run --project Tests/AiPermissionsRegression/AiPermissionsRegression.csproj
dotnet run --project Tests/DownloadQueueRegression/DownloadQueueRegression.csproj
```

Windows 环境还需运行 `Tests/PopupAnimationRegression`，并验证 1.0 与现代版本的真实启动、动态内存预览/保存以及系统运行库安装结果。
