# 触屏输入与版本分流修复

本次以 **26.3 Snapshot 4** 为分界。需求末句的“20.3 第四快照”按上下文解释为“26.3 第四快照”。Mojang 的更新说明确认，此快照将窗口、输入和平台集成库从 GLFW 换为 SDL3，而不是仅更换渲染器。

官方说明：https://www.minecraft.net/en-us/article/minecraft-26-3-snapshot-4

## 修复内容

| 问题 | 修改 |
| --- | --- |
| 旧版拖动视角可能积压、不发送 | 旧路径改用按需启动的输入定时器合并发送位移，不依赖透明悬浮层的渲染回调；保留小数位移，松手前发送剩余位移。 |
| 旧后端光标与回中消息不完整 | 把光标设置请求异步交给游戏；视角模式转发全部原生移动，包括落在虚拟键区域的游戏回中消息。没有新增第二份视角位移，没有修改原始鼠标输入选项。 |
| 双指前进和转视角时下方控制区消失 | 落指使用已确认模式，任何视角、方向键或触摸板触点仍在操作时暂停自动切换；不再在第二根手指落下时释放前进键。 |
| 系统触摸抑制被误判为菜单 | SDL 路径不再以被抑制的残留箭头作为菜单证据；未知样本中断模式确认。 |
| 补丁版本、改名整合包分流错误 | 补丁号不再当作快照序号；真实客户端及原版继承信息优先于改名的实例 ID；缺失快照号不再降格解析成正式版。 |

显式菜单键、隐藏控制区、切换窗口、退出游戏仍会释放按住的输入。手指全部抬起后经过短暂稳定期，再根据持续的菜单或游戏抓取证据更新控制区。

## 分流规则

| 实际游戏版本 | 触屏路径 |
| --- | --- |
| 1.x、旧周快照、26.2 及更早 | GLFW/LWJGL 兼容路径 |
| 26.3 Snapshot 1、2、3（含 T3、第三快照别名） | GLFW/LWJGL 兼容路径 |
| 26.3 Snapshot 4 及以后 | SDL3 路径 |
| 26.3 预发布、候选、正式版及正式补丁版 | SDL3 路径 |
| 后续版本 | 按已知版本规则选新路径；未知或损坏版本信息使用实际窗口后端回退 |

真实继承链底层客户端 JAR 的 `version.json` 优先，`release_target=26.3` 不足以区分 T3 和 T4。之后使用原版继承/客户端版本元数据，最后才使用实例名。

## 验证情况

- 已执行：项目现有的源码检查和 Python 回归检查；输入计时器订阅、卸载及不再依赖渲染回调的检查通过。
- 已补充但未执行：`LegacyTouchRegression` 中 SDL 抑制光标、双指保护、最后一个触点抬起、未知样本打断及菜单恢复的用例；`WorkbenchRegression` 中 T3/T4、中文别名、补丁版、损坏快照名、继承和真实客户端优先级用例。
- 未执行：C# 编译、上述 C# 回归程序，以及 Windows/WPF/游戏触屏运行。当前环境没有 .NET SDK 和 Windows 触屏设备。源码检查不能证明游戏内行为已通过实测。

在安装了 .NET 8 SDK 的 Windows 上，从项目目录执行：

```powershell
dotnet run --project Tests/LegacyTouchRegression/LegacyTouchRegression.csproj
dotnet run --project Tests/WorkbenchRegression/WorkbenchRegression.csproj
dotnet build XCL2.App.csproj -p:SkipNativePreview=true
```

以上构建命令验证 WPF 主程序，不构建 WinUI 预览程序。

## 待进行的 Windows 触屏验收

| 场景 | 预期 |
| --- | --- |
| 1.8.9、1.20.3、26.3 Snapshot 3：进入单人世界和服务器后连续拖动视角 | 视角在拖动期间连续转动，松手时不突然跳转；静止控制界面也能发送输入。 |
| 支持 Raw Input 的旧版本分别开/关该选项 | 两种设置下都验证视角；启动器不改写玩家选项。 |
| 26.3 Snapshot 4 和 26.3 正式版：先按前进，再拖视角 | 同时前进和转向，下方控制区不消失，前进键不被释放。 |
| 先拖视角再按前进；反复抬起其中一指 | 另一根手指继续操作；只有全部抬起后才恢复自动模式判定。 |
| 双指操作期间按 ESC/背包键，再关闭菜单 | 显式菜单操作有效，不残留按键；返回游戏后恢复视角操作。 |
| 加载世界、断线、死亡菜单、重新连接 | 不以加载隐藏光标或触摸抑制错误判定已经进入世界。 |
| 全屏、窗口模式、跨 DPI 屏幕；Alt+Tab、最小化、关闭游戏 | 坐标与窗口一致；失焦/关闭后不残留输入或定时器。 |
| 将 T3/T4 整合包重命名，或使用带继承关系的实例 | 启动日志分别显示 GLFW/LWJGL、SDL3；不受实例名称误导。 |

未来版本仍可能改变输入行为，本次修复不代表对未发布版本或所有驱动的兼容保证。
