# 弹窗、彩蛋与退出修复验收

## 源码行为

- Overlay 使用 `OverlayClosed` 实际关闭通知，涵盖按钮、Esc、背景、非顶层父弹窗、宿主关闭和创建失败清理。`RequestClose` 保留为关闭请求，原生 AI 设置包装器继续用它驱动 DialogResult。
- 每条 Overlay 只结算一次；清理钩子失败不会阻止其他清理或悬挂等待者。实现 IDisposable 的弹窗由宿主释放；任务历史不再在 Esc 关闭后保留静态 Changed 订阅。
- 模态结果使用异步延续；宿主渲染/退场有代次校验，新层拥有自己的内容，旧回调不能覆盖新层。
- 愚人节状态主路径为 `%APPDATA%\XCL2\cdjs\state.json`，首次读取兼容程序目录 `xcl2\cdjs\state.json`。新路径优先；旧副本不会被修改。写入失败保留本次恢复结果，并通过右下角提示说明重启可能再次出现。
- 彩蛋 master 与动画设置直接读取当前配置，立即生效。旧 `noyrj` 注册表开关保存偏好时立即刷新；外部编辑注册表的检查最多延迟1秒，不再在每个16ms动画帧重复打开注册表键。
- 低功耗、完全关闭动画或窗口动画强度0时，不拦截F11。旧60秒原生恢复弹窗注释已删除，实际只使用提醒中心。
- 窗口最小化退出时，保存最后非最小化状态；彩蛋临时移动不会改变该状态。
- “游戏启动后关闭启动器”使用明确的 `PreserveGamesAfterLaunch` 模式，通过 `Close()` 经过关闭备份、插件停止通知及动画收尾；最终不清理游戏/服务器。用户取消关闭后退出模式复位，普通明确退出继续沿用原有清理规则。更新器使用 `RequestExitForUpdateAsync()` 和独立 `PreserveGamesForUpdate` 模式，返回false表示已取消，true仅在实际Closed后完成。

## Windows 必须执行的集成步骤

1. 反复打开任务结果历史，用Esc、关闭按钮、宿主退出分别关闭；继续添加结果，确认关闭实例不再收到回调。
2. 导入预览确认后退场时，模拟异步扫描提示或插件弹窗进入；检查进度/提示的栈顺序，连按Esc后没有遗留遮罩、错误关闭或丢失模态结果。
3. 弹窗内再打开子弹窗，在子层显示期间取消父层；关闭子层后不复活父层。退场过程中退出主窗，所有等待完成且不抛对象已释放异常。
4. 在不可写的程序安装目录以普通用户启动，结束正式日期彩蛋并重启，确认用户目录的当天关闭标记有效；保留旧状态时确认迁移后仍不会再整蛊。
5. 模拟用户状态路径写入失败，按F1仍立即结束本会话，并出现右下角保存失败提示；不自动提高权限。
6. 打开移动彩蛋，逐个切换低功耗、完全关闭动画、窗口动画强度0，确认停止移动且F11可用；恢复动画后遵守当前彩蛋开关。
7. 最大化→最小化→通过外部退出/托盘退出（不先还原），重启确认仍最大化；重复彩蛋移动、F1恢复、最小化后退出。
8. 设置“游戏启动后关闭启动器”和关闭时备份，启动真实游戏：备份结束、插件停止通知结束、启动器退出，游戏进程继续存活。备份失败应记录友好提示后继续原有关闭流程。
9. 关闭备份/插件收尾期间不得重复执行；用户取消关闭后，再次普通退出应恢复原有关闭游戏策略，不继承自动退出的保留游戏模式。

10. 更新器准备就绪后请求关闭，分别取消未保存设置、取消便签关闭、转托盘：API应返回false，更新器收到Abort并停止替换；正常备份/插件/动画完成并真正退出后才可替换。游戏/服务器继续存活。

这些步骤尚未在当前环境执行；不得标记为无Bug或未来兼容性保证。
