# 性能悬浮窗

在设置中展开「性能悬浮窗 · 系统与游戏占用」，勾选「显示性能悬浮窗」并保存。默认关闭，退出启动器时一起关闭。

也可使用 `XCL2.exe --performance` / `--性能设置` 直接到达该区域；调试会话中按 F3 + M 打开。

可显示系统 CPU、系统已用 / 总内存、启动器 CPU / 工作集、各运行游戏的 CPU / 工作集和 PID。详细样式额外显示系统可用内存、逻辑处理器数量及更新时间。CPU 使用整机 0–100% 的口径；进程工作集是操作系统报告的物理内存，不是 JVM 堆上限。首次 CPU 样本、权限不足和读取失败会明确显示等待或不可用，不会假设为 0。

游戏范围可以选择所有运行游戏或指定实例。Java 版使用启动器已有的游戏进程列表；基岩版由采样器识别已知游戏客户端。不会把所有 Java 程序都算作 Minecraft。实例标识包含规范化游戏目录的摘要，不按显示名称合并不同目录的同名实例。同一实例的多个进程各自显示；指定实例退出后保留原选择，不自动切到其他游戏。

左键拖动悬浮窗。右键可以选择简洁 / 详细样式、跟随启动器 / 深色 / 浅色配色、字号、不透明度、显示字段、所有游戏 / 指定运行实例、置顶、位置锁定、位置重置及详细设置。右键更改立即保存，设置页普通编辑沿用原有的手动 / 自动保存流程。右键更改时，已经打开的设置页只同步实际变化的字段，保留其他尚未保存的修改。

详细设置提供 0.5、1、2、5、10 秒刷新周期，自动 / MB / GB 单位，10–26 字号和 25–100% 不透明度。悬浮窗不激活主窗口、不注册全局按键钩子；主窗口最小化或藏入托盘后继续显示。隐藏、关闭或退出时取消采样并停止计时器。

新增选项：窗口宽度可随样式自动调整，或选 280 / 320 / 420 / 520 / 600 逻辑像素；系统内存百分比按总物理内存计算；游戏列表可单独关闭；可显示当前所选范围内的游戏合计，按名称、CPU 或内存排序。合计默认关闭，部分游戏指标不可用时不显示误导性的完整合计。这些选项及刷新周期、内存单位均可从右键菜单更改。

选择“所有运行中的游戏”时收起实例选择框，选择“指定一个游戏实例”时展开。字号和不透明度旁显示当前数值。浮窗滚动条拖动不再触发整窗移动。

## Windows 手工验收

1. 默认配置启动时没有悬浮窗。开启并保存后出现，首次 CPU 等待下一采样点；关闭后无计时采样，重新开启可恢复。
2. 任务管理器使用同一进程工作集及整机 CPU 口径，比较系统、启动器、两份游戏的读数。CPU 首次等待和暂时无权限时不显示假零；读取异常时清除旧数值并显示重试状态。
3. 两个不同目录的同名实例分别有独立选择；指定其中一个后只有该实例显示。退出它以后显示未运行，另一个不会自动补位。选择所有游戏后重新显示全部。
4. 游戏获得焦点时，浮窗显示不会激活主窗口。浮窗以外的键鼠输入继续交给游戏，右键只在浮窗区域出现菜单。锁定后左键不能移动，取消锁定可恢复。
5. 逐个调整样式、字体、不透明度、字段和刷新周期。超出屏幕的已保存位置会被限制回可见工作区。显示很多游戏时能滚动查看，不让窗口无限增高。
6. 在设置页留有未保存的游戏内存修改，再通过浮窗右键更改字号。字号同步且不会丢弃游戏内存修改；离开仍触发原有未保存保护。自动保存回退也同步恢复浮窗设置。
7. 主窗口最小化到托盘后浮窗继续更新。真正退出启动器时浮窗关闭，没有遗留计时器或全局输入钩子。
8. 切换全部 / 指定实例，检查合计范围随之变化；不可用指标排在排序末尾。两个同名实例不混合。修改宽度、刷新周期、内存单位、排序、百分比与合计开关后重启，设置仍保留。

当前工作环境无法运行 WPF / Windows 实机验证；上述步骤用于 Windows 验收，静态检查不能替代这些操作。
