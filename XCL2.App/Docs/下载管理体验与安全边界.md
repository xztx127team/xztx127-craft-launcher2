# 下载管理体验与安全边界

## 默认与入口

搜索、状态筛选、类型筛选、当前阶段和已用时间都放在右上角原有的下载列表内，不新增首页常驻按钮。长名称和状态使用省略号，完整内容可悬停查看。管理操作集中在「管理」菜单；任务行右键只提供针对该任务的操作。

默认不限制任务数，保持旧行为。用户可在「下载列表 → 管理 → 同时执行的任务数」选择 1、2、3、4、8 个。只有真实等待的任务允许上下移动；运行中的任务不会被抢占。单任务内部 HTTP 连接数继续沿用原设置，两个设置含义不同。

「仅重试失败任务」只重放明确支持重试的失败条目。启动前必需的下载、系统安装程序等不可后台重放的条目不会被此按钮重试。恢复的原版 Minecraft 下载仍停在「已暂停」，必须用户主动继续。

固定总限速使用既有设置。Java / 基岩版游戏运行时降速默认关闭，用户可在同一个管理菜单开启并选择 KiB/秒上限；两种上限同时存在时取较小值。共享限速覆盖原版 DownloadService 的单流/分片和 DownloadEndpoints 的文件传输，后者也供通用文件、Java 及多数运行环境下载使用。插件自行创建的网络连接、浏览器下载及系统更新内部传输不在该限速器的控制范围内。

## 进度与空间

进度计数保留真实单位：文件/项的计数不会伪称 MB；统一镜像下载的字节进度明确使用 KiB，并按容量展示偏好格式化大小。「预计剩余」只针对当前阶段，样本不足时显示计算中；未知总量保持不定进度。已用时间只累计真实执行，不累计等待与暂停。

已知清单体积或 HTTP Content-Length 时，在写入/预分配前检查该文件还需要的目标磁盘空间，另预留 16 MB。报错包含目标磁盘、所需与可用空间。无法探测、没有长度或网络盘不支持查询时不编造空间结果；此检查不宣称已计算整个实例的解压后占用。

## 取消与清理

任务结束后，右键「查看进度与文件保留说明」可查看本次实际记录的已完成文件数量，以及已清理/提交和仍保留的临时文件数量。完整文件不因取消而删除。取消暂停中的任务后保留一行已取消的说明，便于核对与清理；再次点击「移除」才收起。完成、失败或已取消的终态行只移除显示，不改写原结果，也不另记一次取消。原版单流 .part 在服务器支持 Range 时可复用，分片中间态和通用下载的 .fbpart 则遵循已有清理规则。

「清理本任务的续传临时文件」必须用户确认，且下载队列无活动任务时才能执行。清理期间新任务保持等待，不会与清理并发写入。它只删除该任务在本次会话内实际登记过、后缀为 .part 且祖先路径没有链接的文件，不扫描目录、不递归删除、不删除最终文件或存档。重启恢复的任务没有本会话的临时文件记录，不提供猜测式清理。

## 验证

`Tests/DownloadQueueRegression` 链接真实队列、恢复、限速和临时文件观察服务，覆盖：真实等待及排序、版本占用、排队中的先决任务取消、仅失败重试、大于桶容量的 buffer、限速取消、游戏限速取较小值、只清理登记的续传文件、已知空间不足不修改文件，以及此前的 Java 安装阶段保护与恢复后不自动执行。

此环境没有 .NET SDK 和 Windows WPF 运行环境，上述 C# 回归源码尚未运行。Windows 验收需实际执行回归项目，并检查不同 DPI、窄列表、深浅主题、长任务名、暂停/继续/取消、UAC 安装期间按钮状态和网络限速。
